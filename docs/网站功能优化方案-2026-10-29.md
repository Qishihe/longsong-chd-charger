# 网站功能优化方案（2026-10-29）

> 只谈**功能**。凭证续期、额度、部署这些另见 `网站更新计划-2026-10-29.md`，本文不重复。
> 所有「现状」均为 2026-10-29 17:00 对 `campus-pile-kit/chd-charge/index.html`（v2.25）的实测，非记忆转述。

---

## 0. 一页结论

**现在这个站只能回答「此刻哪里有空位」，而用户真正要问的是「我 10 分钟后到那儿还有没有位置」。**

所有值得做的功能，都是把这句话从「此刻」推到「到达时」。围绕这个主线分四批，**不要一锅端**：

| 批次 | 主题 | 前置条件 | 版本量 | 风险 |
|---|---|---|---|---|
| **A** | 让现有数据**可信、好找、能走** | 无（纯前端） | 2~3 个版本 | 低 |
| **B** | 让数据**实时且免费**（分区概览 / 7 天曲线 / 秒开） | 快照 Worker 上线 | 2 个版本 | 中 |
| **C** | 让站点**替你决策**（去哪充 / 这个点会不会白跑） | 7 天数据攒够 | 2 个版本 | 中 |
| **D** | 可选增强（定位、提醒） | A~C 稳定后 | 1~2 个版本 | 低 |

一句话：**A 是还债（现在数字不可信），B 是通水（没它 C 全废），C 才是新功能。**

## 1. 现状能力盘点（实测，不是印象）

### 1.1 已经有的

| 能力 | 实现位置 | 备注 |
|---|---|---|
| 109 台桩卡片列表 | `render()` | 每台 4 插座 = 436 口 |
| 地址筛选 + 排序（编号/空闲/收藏） | `renderLocationFilter()` / `applyFilterSort()` | — |
| 收藏 | `setFav()` / `getFavs()`，存 `cpk.fav` | 只影响排序，无提醒 |
| 地图（4 分区 + 高德真图） | `openMap()` / `switchMap()` / `map-amap.js` | 可点桩看详情 |
| 自动刷新 | `applyAutoRefresh()` | **10 分钟 ±60s，只打 1 个汇总请求** |
| 深色模式 | `@media (prefers-color-scheme: dark)` | 已有，不用做 |
| 手动刷新（逐台） | `refresh()` | 109 台分 9 批，`CHUNK=12` / `LANES=2` |
| 历史统计弹窗 | `#usage-dialog` | 🔴 **入口已下线**，且云端 402，实际不可用 |

### 1.2 缺的（本次 grep 实测为 0）

| 缺口 | 证据 |
|---|---|
| **搜索框** | 全页只有 2 个下拉 + 2 个密码框，无文本搜索 |
| **导航跳转** | `uri.amap.com` / `map.qq.com` / 导航相关代码 **0 处** |
| **地理定位** | `geolocation` **0 处** |
| **通知** | `Notification` / `requestPermission` **0 处** |
| **分区汇总** | `shopOverviewOnce()` 只返回**一个全站 `available` 数**，没有分区拆分 |

### 1.3 一个必须正视的事实

```
自动刷新（每 10 分钟）→ 只调 refreshOverview() → 只拿全站一个数字
逐台明细（109 台）  → 只有「手点刷新」和「换地址筛选」才发生
```

后果：**页面开着不动，卡片数据永远不会自己更新。** 卡片上「旧记录」的阈值是 3 分钟（`Date.now() - record.at > 180000`），所以开着一个页面十分钟后，**几乎每张卡都会挂上「旧记录」**——用户看到一片黄色标记，却没有任何办法让它变新。

这不是 bug，是 10-23 那次「刷新图标一直转」事故之后为了风控做的主动收敛。但它带来了真实的信任问题：**站点的数字看起来像实时，其实经常是半小时前的。**

这条是 A 批存在的全部理由。

## 2. 三个真瓶颈

1. **可信度**：数据多新，完全靠用户自己去猜「旧记录」那几个字，且没有"一键变新"的出口。
2. **决策缺席**：站点把 109 行数字摊给你，把判断留给你。用户要的不是数据，是「去哪」。
3. **行动断点**：看完知道北门有空位，然后就……没了。没有导航、没有距离、没有"要不要现在出发"。

对应 A / C / A（导航）三批。B 是让 1 和 2 有可能做对的地基。

## 3. 功能清单

### 批次 A · 纯前端，零新增上游请求

> 硬约束：**A 批所有功能都不许增加一次平台请求**。任何需要新数据的想法，一律推到 B 批。

#### A1. 数据新鲜度分级 + 过期置灰 + 一键刷新 ★最高优先

- **解决**：用户分不清哪个数字能信。
- **做法**：
  - 卡片三档：`<3 分钟`（正常）／`3~30 分钟`（黄边 + "25 分钟前"）／`>30 分钟`（**数字置灰 + 斜纹**，并写"建议刷新"）。
  - 顶部 `#s-time` 换成"数据最老一台是 X 分钟前"，而不是"更新时间"（现在只显示最新那台，属于美化）。
  - 顶部黄色 banner：超过 30 分钟时出现「数据已 35 分钟未更新 · 点此刷新」。
- **落点**：`render()` 里 `stale` 那段、`#stats`、`paintBanner()`。
- **成本**：小（约 80 行）。
- **验收**：手机开着页面 35 分钟不点任何东西，必须出现 banner，且卡片数字肉眼可辨为"旧"。

#### A2. 搜索框

- **解决**：109 张卡片只能滚；想找 "TY-07" 得翻半天。
- **做法**：`#toolbar` 里加 `<input type="search">`，匹配 `code`（TY-07）、`name`、`location`；输入即过滤，空结果给"没有匹配的桩"。
- **落点**：`#toolbar`、`applyFilterSort()`、`getFilter()` 附近新增 `cpk.q` 持久化。
- **成本**：小（约 60 行）。
- **注意**：搜索是**纯前端过滤**，不触发请求；与地址下拉是 AND 关系。
- **验收**：输入 `ty-0` 大小写混合能命中；清空后恢复全量。

#### A3. 一键导航 ★性价比最高

- **解决**：知道有空位，但不知道在哪、怎么走。地图只能看，不能"走"。
- **做法**：
  - 地图桩点详情、分区圈、以及卡片上加「导航」按钮。
  - 手机唤起高德：`https://uri.amap.com/marker?position={lng},{lat}&name={名称}&src=chd-charge`
  - 坐标已是 GCJ-02（`map-data.js` 头注释写明），高德/腾讯可直接用，**不要做坐标转换**。
  - PC 上该链接会打开高德网页版，行为可接受。
- **落点**：`pinCoord()` 已有坐标；新增 `navTo(device)`，在 `renderMapMarkers()` / 桩点详情里挂按钮。
- **成本**：小（约 50 行 + 2 个按钮样式）。
- **风险**：低。唯一注意——iOS 上不带 `target=_blank` 才会唤起 App。
- **验收**：手机点导航 → 高德 App 打开到该桩，起点为当前位置。

#### A4. 断网 / 加载失败兜底

- **解决**：校园网不稳，现在失败就一片红"状态未知"，用户以为桩坏了。
- **做法**：
  - 记住最后一次成功快照到 `localStorage`（带时间戳）。
  - 断网或全批失败时，展示"最后已知状态（2 小时前）"+ 明显灰化，**而不是**"状态未知"，并在顶部说明"当前网络不可用，显示的是历史数据"。
- **落点**：`paintCardError()`、`readCache()`、`refresh()` 的 catch 分支。
- **成本**：中（约 120 行，涉及状态语义，别和"未知=占用"的红线搞混）。
- **🔴 红线**：10-20 定过"查询失败不要保留上次好数据假装还绿"。所以这里不能把旧数据渲染成绿色正常卡，**必须整块降级视觉**（灰底 + 明确时间 + 顶部提示）。语义上区分 `stale`（旧但真）与 `unknown`（不知道）。
- **验收**：飞行模式刷新，页面不白、不谎报实况、时间标注正确。

#### A5. 卡片趋势微图（可选）

- **做法**：页面打开期间，把每次采样写进内存环形缓冲（不落盘、不请求），卡片右上角画 12 点 sparkline。
- **成本**：小（约 70 行）。
- **诚实边界**：只反映"你看页面的这段时间"，不是历史；界面上要写清"本次浏览"，否则会误导。

#### A6. PWA 装到桌面

- `manifest.webmanifest` 已有，只需加一条首次访问的轻提示（可关闭、`localStorage` 记一次）。
- **成本**：极小（约 30 行）。

### 批次 B · 依赖快照 Worker（这是功能总闸门）

> 只有 B 落地，A1 的"数据不可信"才算根治，C 批才有数据可用。

#### B0. 前提：先有 `/api/snap`

Worker 端定时抓 4 个分区、全员共享，前端零新增上游压力。部署细节见 `snapshot-worker/DEPLOY-CHECKLIST.md`。

**这一步不是"基础设施"，它是 A1/B1/B2/C 全部的前提。** 值得在排期里当第一优先级的功能项看。

#### B1. 分区概览条 ★

- **解决**：现在要知道各区情况，得进地图或滚列表；而全站一个数字没意义（"还有 40 个空位"可能在最远的区）。
- **做法**：首页顶部 4 个块：

  ```
  北门        12/148   ↑2   3 分钟前
  朝晖体育场   4/144   ↓1   3 分钟前
  20 号楼      9/96    →    3 分钟前
  物业服务中心  1/48    ↓3   3 分钟前
  ```

  点块 = 筛选到该区；长按/右滑 = 导航。
- **依赖**：`/api/snap` 必须返回**分区级** `{area, free, total, age}`。⚠️ 现在的 `/api/pile` 汇总接口给不了，别试图在纯前端硬算（逐台数据是旧的）。
- **成本**：中（Worker 侧 1 天 + 前端 1 天）。
- **验收**：4 区数字之和 == 顶部全站空闲数。

#### B2. 7 天占用率热力图（复活 `#usage-dialog`）

- **做法**：不要恢复原来那条 24 小时折线（分辨不出"周三下午"和"周日下午"）。改成 **7×24 热力图**：横轴小时、纵轴星期、颜色 = 占用率。点格子看"该时段平均空闲 N 个 / 观测 X 次"。
- **依赖**：D1 里至少 7 天数据；采样来自 cron，约 456 轮/天。
- **成本**：中（约 250 行 + 一个不需要库的 SVG/canvas 渲染）。
- **红线**：观测次数 < 3 的格子要留空（斜纹），不要拿 1 个样本画满色块。
- **验收**：随机抽 5 个格子，与 D1 原始聚合行手算一致。

#### B3. 首屏秒开

- `refresh=0` 先渲快照，再异步补刷。六条规则见 `网站更新计划` §5.2，**逐条照做**，尤其第 3 条（`ok:false` 不许清空界面）和第 5 条（`Age` 头要加）。

### 批次 C · 有了 7 天数据才成立

> 🔴 这一批最容易做成"看起来很聪明其实在编"。**凡是数据支撑不住的，宁可输出"不知道"。**

#### C1. 「去哪充」推荐卡

- **输入**：各区当前空闲、到各区的步行时间、该时段历史平均空闲、数据新鲜度。
- **输出**：一个排序 + 一句人话理由：

  > **去北门**：现在 12 个空位，步行约 6 分钟；这个点过去 7 天平均也有 9 个空位。

- **算法（务实版，别搞伪精确）**：
  ```
  score = 0.6 * 归一化(当前空闲) + 0.3 * 归一化(同刻历史平均空闲) + 0.1 * 新鲜度
  最终排序只在第一名显著领先（差值 > 15%）时给"推荐"，否则直接说"三个区都差不多，选最近的"
  ```
- **依赖**：B1 + B2 + 一份**步行时间矩阵**（需要实地/地图测一次，静态数据即可，不用实时算路）。
- **成本**：中大（3 天，其中步行矩阵要人量）。
- **风险**：给错推荐比不给更糟。所以**只在置信度足够时说话**，其余时候老实说"数据不足"。

#### C2. 「这个点会不会白跑」

- **做法**：以区为单位，输出一句统计事实：

  > 过去 7 天，14:00–15:00 到北门有 **38%** 的观测是 0 空位。

  即 `P(空闲==0)`，直接从热力图数据算，**不需要模型**。
- **成本**：小（约 80 行，纯前端读聚合接口）。
- **价值**：这是全站最诚实也最有用的一个数字。

#### C3. 满桩时的替代建议

- 某区 0 空位时，卡片上直接写"最近的替代：物业服务中心 3 个空位（步行 4 分钟）"。
- **成本**：小（约 50 行，复用 C1 的数据）。

## 4. 明确不做（附理由）

| 不做 | 理由 |
|---|---|
| 账号 / 登录 / 个人中心 | 本站是只读查询，账号不带来任何新能力，只带来合规与维护成本 |
| 扫码充电 / 支付 / 订单 | 越界。站点定位是"查询"，碰交易就变成另一件事 |
| 提高自动刷新频率 / 逐台轮询 | 风控红线（`PILE_CONCURRENCY=6` / `CHUNK=12` / `LANES=2` 已定死）。想更快只能走 B 的服务端快照 |
| 实时 WebSocket | 上游没有推送能力，幻想 |
| 评论 / 社区 / 打分 | 审核成本高，QQ 群已覆盖这个需求 |
| 精确"预计等待 N 分钟" | 现有采样是**小时级聚合**，没有插座级周转数据，算出来的分钟数是编的。改做 C2 的"白跑率"，同样有用且诚实 |

## 5. 发布纪律（别在功能上翻船）

每批功能按项目既有红线走，一条都别省：

1. **先只改 `preview.html`**，`#app-ver` + 所有 `?v=N` + `sw.js` 的 `CACHE` 同步升；`SHELL` 里 `map-data.js?v=N` 必须与页面同串。
2. **一个版本只装一~两个功能**，不要合并发布——出问题定位不了。
3. 动 localStorage 的（A2 搜索词、A4 快照缓存）**必须两版同上**。
4. 地图相关改动（A3 导航）**必须用 CDP 真鼠标验**，`el.click()` 对聚合圈无效。
5. 同步正式版后**必跑** `check_dual_track.py`（两版体积差 ≈ 2563）。
6. 改 Python 生成 HTML 时**保 LF**（`write_text` 会写 CRLF）。
7. 快照三件；整包回退 8 件。

## 6. 建议起步顺序

如果只做三件事，按这个顺序：

1. **A1 数据新鲜度**（半天）—— 现在就有一片"旧记录"在骗人，先止血。
2. **A3 一键导航**（半天）—— 投入最小、直接促成一次真实到店，用户感知最强。
3. **B1 分区概览**（2 天，含 Worker 侧）—— 让首页从"109 行数字"变成"4 个决策"。

A2 搜索、A4 断网兜底可以跟着 1 一起发。

C 批**必须等数据**：现在 D1 里一天都没有，7 天数据最早也要到 11 月中。所以 C 的排期起点是"B 上线 + 7 天"，不是日历上的某天。

## 7. 一个顺手要清的小问题

`map-data.js` 的 `areas` 里还留着旧分区名 `渭水-物流服务中心`（只有 `line`/`zoom`，无桩）。它已在 10-24 被 `LOCATION_RENAMES` 改名为「物业服务中心」，但**地图数据里那份旧条目没删**。目前因为没有设备引用它，不会渲染出来，属于潜伏项——下次动 `map-data.js` 时一并清掉，别新增第五个 tab。
