## 2. P0 · 拉起续期守护（今天，5 分钟，你动手）

### 2.1 操作

二选一：

**方式 A（快）**：双击
```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\chd-token-autorenew.vbs
```

**方式 B（稳）**：注销后重新登录 Windows（启动夹会自动执行）。

### 2.2 为什么必须你动手

不是偷懒。三条路都试过并失败：

| 尝试 | 结果 |
|---|---|
| `Start-Process` 起 VBS | 进程随本次工具调用的 job object 一起被收，活约 3 分钟 |
| `CREATE_BREAKAWAY_FROM_JOB` | `WinError 5` 拒绝访问 |
| `explorer.exe <vbs>` | 根本不执行，实测 marker 文件都没出现 |

VBS 用 `WScript.Shell.Run(..., 0, False)` 拉起 `pythonw.exe`，但只要父进程在被管理的 job 里，子进程就会被连带杀掉。**只有你在会话外亲手启动，它才能活过我的调用。**

### 2.3 验证（你做，或我做）

```bash
# 1) 进程在不在
powershell -c "(Get-CimInstance Win32_Process -Filter \"Name='pythonw.exe'\").Count"

# 2) 日志有没有新行（应出现「守护启动，每 600 秒检查一次」）
tail -5 ~/.chd_token_autorenew.log
```

判据：进程数 ≥ 1，且日志末尾出现 10-29 之后的「检查：ok → none」。

## 3. P1 · 演练真续期（**11-01 前必须完成**）

### 3.1 为什么不能等 11-03 自动触发

这是本次核查最重要的发现：

```
SOON_HOURS = 6.0   →  剩不到 6 小时才动手
```

也就是说守护要到 **11-03 10:06** 才开始尝试，距过期只剩 6 小时。而这 6 小时里：

- 失败重试间隔 1200 秒（20 分钟）→ 最多约 19 次机会
- 每次尝试要现场起 Fiddler、把微信小程序拉到前台、等人扫码/进入页面
- 如果那天你在上课、在开会、微信没登录、Fiddler 起不来（历史上有自动退出、代理留 8888 导致整机断网的前科）→ **没有第二次机会**

**结论：必须提前手动演练一次真换新，把「守护能不能跑通」这件事从 11-03 的赌局变成已知事实。**

### 3.2 演练步骤

**Step 1 — 空跑（不启动 Fiddler、不上传）**

```bash
python campus-pile-kit/tools/token_autorenew.py --once --dry-run
```

看它「本来会做什么」。此步无副作用，可随时跑。

**Step 2 — 真演练（强制换一张新凭证）**

```bash
python campus-pile-kit/tools/token_autorenew.py --renew
```

`--renew` 会：起 Fiddler → 把微信拉到前台 → 等你进小程序 → 抓新 token → 接口验证 → 上传 → 回读确认。

> **需要你在场**：微信要已登录，并在它拉起时进入充电桩小程序页面。
> 全程约几分钟，日志会实时打印每一步。

**Step 3 — 确认**

```bash
python campus-pile-kit/tools/token_autorenew.py --status
```

判据：
- 「站点在用」的到期时间**变成新的**（比 11-03 更晚）
- 日志出现「回读确认：信箱里已经是这串」

### 3.3 已知坑与兜底

| 坑 | 表现 | 兜底 |
|---|---|---|
| Fiddler 起后自己退 | 日志卡在「等待新凭证」 | 重新 `--renew`；确认 Fiddler 版本可启动 |
| 代理留在 8888 | **整机断网** | `python campus-pile-kit/tools/token_autorenew.py --fixproxy` |
| 反代域名丢口令头 | `bad_token` | 工具已自动改走 pages.dev（见日志） |
| 抓到旧凭证 | 「接口验证没通过」 | 重新进小程序，让页面真正刷新一次数据 |

> 10-27 日志里的「回读提示：信箱 exp=—」是**当时** Worker 尚未返回 `expiresAt` 的历史现象。
> 现已修复：`box_tool.mjs` 第 129 行把 `expiresAt` 映射为 `exp`，本次 `--status` 能正确读出到期时间。
> **演练时如果还出现 `exp=—`，说明字段契约又漂了，先查这里再继续。**

### 3.4 演练失败怎么办

若 11-01 前演练连续失败：

1. 不要拖到 11-03。**11-02 当天向业务方/上游确认是否有长期凭证或后台可手工换发**。
2. 同时评估「站点暂时降级」：到期后页面仍在、地图仍可看，但数据全空。可先挂一条说明文案，避免用户以为坏了。

## 4. P2 · 部署快照 Worker（无硬期，但越早越好）

详细步骤见 `campus-pile-kit/snapshot-worker/DEPLOY-CHECKLIST.md`，此处只列**你必须参与的点**和验收判据。

### 4.1 你需要做的（约 5 分钟）

```bash
cd campus-pile-kit/snapshot-worker
npx wrangler login      # 浏览器授权，点一次
npx wrangler whoami     # 确认 account_id 出现
```

把 `account_id` 告诉我（或直接填进 `wrangler.toml`）。

### 4.2 我做的

```bash
# 1) 建库（不需要绑卡）
npx wrangler d1 create chd-snap          # 拿 database_id → 填 wrangler.toml

# 2) 建表（🔴 必须先于 deploy）
npx wrangler d1 execute chd-snap --remote --file=migrations/0001_init.sql

# 3) 内部密钥（同一串，两处都要）
npx wrangler secret put SNAP_KEY
npx wrangler pages secret put SNAP_KEY --project-name chd-charge

# 4) 上线
npx wrangler deploy
```

### 4.3 验收（一条都不能跳）

| 检查 | 命令 | 判据 |
|---|---|---|
| **锁原子性** | `node tools/verify_snapshot_lock.mjs "$BASE" --wait` | 并发 5 个 `refresh=1`，只能 1 个 `refreshed:true` |
| **cron 真跑完** | Dashboard → Trigger Events | 无 `exceededCpu`（免费版每次 cron 仅 10ms CPU） |
| **不超龄** | `curl "$BASE/api/health?fresh=1"` | `overdue` 不全为 true |
| **手动取数** | `POST $BASE/api/snap` | 返回 `ok:true` 且 `piles`>0 |

> 🔴 `migration` 与 `deploy` 必须**分开、按序**执行。顺序反了绑定名/表名对不上，全站瞬间 500。
> 🔴 免费版每账号只有 5 条 cron，本方案用满（4 分区 + 1 统计），以后再加定时 Worker 会部署失败。

### 4.4 收益与代价

| | |
|---|---|
| 收益 | 历史数据恢复（每天约 456 轮定时抓取）；上游压力从「每访客可能回源」降到「定时抓+缓存」；7 天曲线成为可能 |
| 代价 | D1 免费额度约用 3%（典型）/ 9.6%（最坏），不用绑卡 |

## 5. P3 · 前端接入 `/api/snap`（依赖 P2）

### 5.1 双轨流程（项目红线）

1. **先只改 `preview.html`**，`?v=N` 与 `#app-ver` 同步升，`sw.js` 的 `CACHE` 同步升
2. 用 CDP 真鼠标验证（`el.click()` 对聚合圈无效）
3. 通过后 `python scratch/sync_index_v214.py --apply` 同步正式版
4. **必须**跑 `check_dual_track.py`，确认两版体积差 ≈ 2563

### 5.2 六条硬规则（写错就把后端所有修复作废）

1. 首屏 `refresh=0` 先渲染快照，再异步 `refresh=1` 补刷
2. 判断数据可用看 `snapshot.valid`，不能只看 `piles`
3. `ok === false` **不要清空界面**，保留上次渲染 + 顶部提示
4. `rate_limited === true` **不要重拉**（重拉仍是同一片，会被挡）
5. 显示「x 分钟前」要加 `Age` 响应头：`realAge = snapshot.age + Age`
6. `?area=all` 不支持补刷，收到 `refresh_ignored` 后对 `oldest_key` 单独补一次

### 5.3 关键语义

`/api/snap` 降级时返回 **HTTP 200 + `ok:false`**，这是故意的——5xx 会让前端抛异常把已有界面换成白屏。
