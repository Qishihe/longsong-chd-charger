# 设备清单管理（编号脱敏）

仓库是公开的，所以 `chd-charge/index.html` 的 `DEFAULT_DEVICES`、
`snapshot-worker/partitions.mjs` 里写的都是 `PILE0001` … `PILE0200` 这类**占位符**，
`map-amap.js` 里还有一层约 300 m 的 `GEO_SHIFT` 演示偏移。

真实编号在那份**不入库**的私有清单里：

```
campus-pile-kit/private/devices.private.json
```

> ⚠️ 这份文件是设备编号的唯一真值来源，`.gitignore` 已排除。
> 丢了就等于丢了整份设备清单（打包注入、快照部署、凭证探针全都读它）。
> 备份：`D:\chd-backup\`（`repo-before-scrub-20261121.bundle` 之外的单独副本）。

## 为什么这么做

公开仓库里原来躺着 200 台设备的真实平台编号，还有一套能从像素几何推回精确
落点的数据 —— clone 下来就能直接打 `/api/pile` 查任意桩的实时状态。
脱敏后仓库里只剩占位符与偏移后的示意坐标。

**注意这只挡住爬虫和搜索，挡不住人**：线上站点本身就是公开查询页，
按 F12 一样能看到全部编号。它解决的是「开源仓库不该躺明文清单」，不是保密。

## 打包（Pages）

```bash
python tools/make_cloudflare.py
```

`make_cloudflare.py` 读文件后**先在内存里注入**（占位符 → 真号、`GEO_SHIFT` 归零）
再交给 esbuild 压缩。源码文件一个字节都不动。

🔴 注入必须在压缩**之前**：esbuild 会把 IIFE 里的 `var GEO_SHIFT` 改名，
压完就找不到锚点了。

`catalog.json` 由 `gen_catalog.py` 从公开源码解析（id 是占位符），落盘后补一次注入。

验收标准（改完注入链路后必跑）：

```bash
python tools/inject_private.py --verify dist-cloudflare
```

## 本地预览

**别直接拿 `chd-charge/` 当站点看** —— 桩点会飘到校区外、徽章与桩阵错位。

```bash
python tools/inject_private.py --out scratch/_devsite
python campus-pile-kit/chd-charge/serve_gzip.py --root scratch/_devsite --port 8909
```

或者直接用打包产物 `dist-cloudflare/`。

## 快照 Worker 部署

`partitions.mjs` 是占位符，**不能直接 `wrangler deploy`** —— 会拿一串假号去打
平台，每台都「平台没响应」，而且 cron 静默失败没人发现。

```bash
python tools/gen_snapshot_partitions.py --inject     # 生成 snapshot-worker/.deploy/
cd snapshot-worker/.deploy && wrangler deploy
```

`.deploy/` 含真号，已在 `.gitignore` 里，**绝不能提交**。

## 加设备 / 改编号

1. 在私有清单里加一条：`{"ph": "PILE0201", "id": "真实编号", "code": "...", ...}`；
2. 在 `index.html` 的 `DEFAULT_DEVICES` 里用 `PILE0201`；
3. `python tools/gen_snapshot_partitions.py` 重新生成分区清单；
4. 打包 + `--verify`。

新增分区的 11 处联动不变（见 `MEMORY.md`）。

## 守门

`python tools/check_release.py` 有两条相关检查：

- **源码里没有真实设备号**（`XL[AB]\d{5}` / `id: '86\d{13}'`）—— 防手滑复制粘贴旧代码；
- **`campus-pile-kit/private/` 在 `.gitignore` 里**。

## 凭证探针

`tools/cred_grab.py` 的 `PROBE_IDS` 从私有清单取第一台走中民的设备。
清单缺失会**直接报错**——静默退化成占位符会让 `verify()` 永远验不过 token。
